# 多 API、多模型生图配置

用户只选择模型。服务端负责把模型 ID 映射到准确的上游模型名、请求参数、API 地址和密钥；积分也按选中的模型报价。

## 两层配置

- `IMAGE_CHANNELS` 管理连接：`name`、`baseUrl`、`apiKeyEnv` 或 `apiKey`、`priority`、`enabled`。优先级数值越小越先尝试。
- `IMAGE_MODELS` 管理模型：`id`、`label`、`upstreamModel`、`apiFormat`、`channels`、积分和成本。每个自定义模型必须显式绑定通道。
- 一个通道可供多个模型使用；一个模型也可绑定多个同模型通道。备用通道不会跨到另一种模型。
- `IMAGE_MODEL_DEFAULT` 只决定未选择模型时的默认项，不会覆盖用户明确选择的模型。
- 模型 ID 应保持稳定，例如 `openai:gpt-image-2`、`xai:grok-imagine-image`。`label` 是用户看到的名称，`upstreamModel` 必须填写上游实际接受的名称，三者不要混用。
- `openai` 在这里表示兼容 Images API 的传输适配器，并不表示把所有模型变成 OpenAI 模型。

## 配置示例

以下内容供手动填写根目录 `.env`，不会自动修改已有配置。域名和密钥均为占位内容，价格仅用于演示，必须按自己的收费及真实成本调整。

```dotenv
IMAGE_PROVIDER_DEFAULT=openai
IMAGE_MODEL_DEFAULT=openai:gpt-image-2

GPT_IMAGE_API_KEY=在本机填写GPT通道密钥
GROK_IMAGE_API_KEY=在本机填写Grok通道密钥

IMAGE_CHANNELS='[
  {"name":"gpt-main","baseUrl":"https://gpt-gateway.example/v1","apiKeyEnv":"GPT_IMAGE_API_KEY","priority":0},
  {"name":"grok-main","baseUrl":"https://grok-gateway.example/v1","apiKeyEnv":"GROK_IMAGE_API_KEY","priority":1}
]'

IMAGE_MODELS='[
  {
    "id":"openai:gpt-image-2",
    "label":"GPT Image 2",
    "upstreamModel":"gpt-image-2",
    "apiFormat":"gpt-image",
    "channels":["gpt-main"],
    "creditsPerImage":7,
    "costCentsPerImage":4
  },
  {
    "id":"xai:grok-imagine-image",
    "label":"Grok Imagine",
    "upstreamModel":"grok-imagine-image",
    "apiFormat":"grok-image",
    "channels":["grok-main"],
    "creditsPerImage":3,
    "costCentsPerImage":2
  },
  {
    "id":"xai:grok-imagine-image-2.0",
    "label":"Grok Imagine 2.0",
    "upstreamModel":"grok-imagine-image-2.0",
    "apiFormat":"grok-image",
    "channels":["grok-main"],
    "creditsPerImage":5,
    "costCentsPerImage":3
  }
]'
```

只有供应商确实提供对应模型、密钥有权限，并且支持所选请求格式时，才添加该模型。示例中的模型名不是对任意网关可用性的保证；`/models` 返回模型也不等于支持 `/images/generations`。模型列表来自本地白名单配置，不会根据不可信上游响应自动新增模型。

`baseUrl` 填 API 根地址，例如以 `/v1` 结尾；不要填写完整 `/images/generations`。系统会自动拼接该路径。`apiKeyEnv` 是环境变量名称，不是密钥内容；也可继续使用旧的 `apiKey` 字段，但两者不能同时填写。真实凭据只保存在服务端环境变量中，不要提交到 Git。

## 请求格式与能力

| `apiFormat` | 请求参数 | 默认画质选项 |
|---|---|---|
| `gpt-image` | `model/prompt/n/size/quality/response_format/output_format`，保持原有 GPT 生图协议 | 草稿、标准、高质 |
| `grok-image` | `model/prompt/n/aspect_ratio/response_format`，不发送 GPT 专有的画质与输出格式参数 | 标准 |
| `openai-images` | 最小兼容参数 `model/prompt/n/size/response_format` | 标准 |

以上均调用 `POST /images/generations` 并请求 `b64_json`，也兼容项目原有的图片 URL 响应处理。仅提供聊天、Responses、Gemini 原生或异步任务协议的服务不能只换地址接入，仍需新增对应适配器。参考图编辑仍未接入，不会把图生图伪装成文本生图。

Grok 的比例、Base64 和 Images 端点已按 [xAI 官方生图文档](https://docs.x.ai/developers/model-capabilities/images/generation) 核对。当前 `grok-image` 适配器只开放“标准”选项，不发送 `quality` 或 `resolution`，采用上游默认值；这不是说 Grok 2.0 本身没有其他质量能力。第三方网关仍需单独验收。

模型可增加 `qualities`、`aspectRatios` 和 `maxQuantity` 缩小能力范围。例如 `"qualities":["standard"], "aspectRatios":["1:1","16:9"], "maxQuantity":2`。请求格式不支持的画质不能通过配置强行开启。正向提示词继续保持全局 7000 字符上限。

首页和工作台使用同一模型目录。切换模型时会同步调整不支持的画质、比例和张数；工作台重新报价。停用模型或没有启用通道的模型不出现在列表中；历史链接指定的不可用模型会提示重新选择，而不会默默换成 GPT。

## 计费和同模型备用通道

`creditsPerImage` 是标准方图的基础积分。最终积分为 `ceil(基础积分 × 画质系数 × 尺寸系数 × 张数)`。`gpt-image` 默认沿用原系数：草稿 0.75、标准 1、高质 1.7；非方图尺寸系数 1.22。其他格式默认系数均为 1，可用 `qualityMultiplier` / `sizeMultiplier` 显式覆盖。

`costCentsPerImage` 为基础供应商成本，单位是分；它不会发送到前端。不同供应商成本不同时，可以在绑定处覆盖，而不能给全部模型沿用同一通道价格：

```json
{
  "channels": [
    "gpt-main",
    {"name":"gpt-backup","upstreamModel":"供应商实际的同模型别名","costCentsPerImage":6}
  ]
}
```

`gpt-backup` 必须先在 `IMAGE_CHANNELS` 中配置。显式模型绑定优先采用绑定的 `upstreamModel`，未指定时使用模型自身的上游名；不会使用旧的通道级模型名覆盖用户选中的模型。不要把不同模型当作别名绑定。失败退款、按张切换和现有熔断策略继续保留。超时后的切换默认仍关闭，避免上游已经生成但重发导致重复收费。

## 校验与生效

在项目根目录执行只读校验，只输出公开模型列表，不发送生图请求：

```bash
node --env-file=.env --input-type=module -e "import { getImageModelCatalog } from './packages/ai-providers/dist/index.js'; console.log(JSON.stringify(getImageModelCatalog(), null, 2))"
```

首次更新代码后先执行 `npm run build:packages`。校验通过后，停止旧 API 和 Worker，再分别执行 `npm run dev:api`、`npm run dev:worker`；前端执行 `npm run dev:web`。API 与 Worker 必须加载同一份配置，只刷新页面不能加载服务端的新环境变量。

可通过 `GET http://127.0.0.1:4100/api/generation/models` 检查生效目录。最后再自行选择模型进行真实生图验收，该步骤可能产生供应商费用。

未配置 `IMAGE_MODELS` 时保持旧单模型模式；配置为 `[]` 表示没有可用真实模型，不会回退旧通道。`IMAGE_CHANNELS` 仍优先于 `OPENAI_BASE_URL` / `OPENAI_API_KEY`。不要在仍有排队任务时删除其模型配置，避免旧任务因模型停用而失败退款。
