# 本地启动与服务端口

## 固定端口

| 服务 | 端口 | 命令 |
| --- | --- | --- |
| Web | `3100` | `npm run dev:web` |
| API | `4100` | `npm run dev:api` |
| Worker | 无固定 HTTP 端口 | `npm run dev:worker` |

前端默认会把本地 API 指向 `http://127.0.0.1:4100`。相关逻辑在 `apps/web/lib/api.ts`。

## 常用命令

```powershell
npm run dev:web
npm run dev:api
npm run dev:worker
npm run typecheck
npm run build
npm run docs:maintenance
```

`apps/web` 和 `apps/api` 的 dev 脚本会跑 `infra/scripts/dev-preflight.mjs`，用于清理 Windows 上常见的端口占用和 Prisma 临时文件残留。

## 健康检查

API：

```powershell
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:4100/health | Select-Object -ExpandProperty Content
```

Web：

```powershell
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:3100/generate | Select-Object -ExpandProperty StatusCode
```

## 本地数据和环境

本地常见组合是 JSON store、inline queue、本地或兼容 provider。真正生产环境需要补齐真实 provider、对象存储、支付、Redis、SMTP 等配置。

不要在维护文档里写真实密钥。涉及 `.env`、token、证书、CI/CD 的改动必须先确认，不要顺手改。

## 反向代理与客户端 IP

升级到 Fastify 5.12.5 后，API 默认不信任 `X-Forwarded-For` 等转发头，`TRUST_PROXY` 未配置、`false` 或 `0` 时均按直连 IP 限流。生产环境位于反向代理后面时，需要显式配置可信代理 IP 或 CIDR，多个地址用逗号分隔，例如代理确实在本机时使用 `127.0.0.1/32,::1/128`。地址应匹配 API 实际收到连接的代理出口；容器或网关部署不能直接照抄本机地址。

旧的 `TRUST_PROXY=1` 等非零数字跳数配置会让 API 启动失败，必须改为可信代理 IP/CIDR。不要用 `true` 代替迁移：它会信任所有来源的转发头，直连客户端可能伪造 IP 绕过限流。代理还需要正确覆盖或追加转发头，部署网络应限制 API 只能通过预期入口访问。

如果代理地址未加入信任列表，API 会把代理后的所有用户计入同一个 IP 限流桶；排查大量用户同时遇到 `429 RATE_LIMITED` 时，先检查可信代理配置。`tests/redis-rate-limit.test.mjs` 覆盖默认拒绝伪造转发头、可信/不可信代理、转发链边界和旧数字配置启动失败。

## 安全依赖与安装验证

2026-09-27 的安全更新使用 Next.js `16.3.6`、Fastify `5.12.5`、sharp `0.35.4`，根 `overrides` 固定 PostCSS `8.5.28` 和 deepmerge-ts `8.0.2`。后者覆盖 Prisma `6.19.3` 的间接依赖，因此更新 Prisma 时要保留 `tests/dependency-compatibility.test.mjs` 的真实配置加载回归，并运行 `prisma:validate` / `prisma:generate`。这些校验及客户端生成不会修改数据库。

提交依赖变更时同步 `package-lock.json`，使用 `npm ci` 验证新环境安装，再运行 `npm audit --omit=dev` 和完整 `npm audit`。本轮锁文件在独立目录安装后两项审计均为 0 漏洞，Next.js 生产构建、Prisma 配置加载与图片生成/缩略图回归通过。

当前 npm `11.8.0` 的工作区链接会丢失传给依赖目标节点的 overrides 信息，`npm ls` 因而仍将 PostCSS / deepmerge-ts 标为 `invalid`（对比的是上游原始固定版本）。该提示在干净安装后也可复现；实际安装及运行的是上面的安全版本。不要为消除提示而退回旧依赖，后续升级 npm 或上游包时复查依赖树、锁文件与审计结果。

## 自动地图更新

改了 API 路由、页面、包结构或环境变量引用后，运行：

```powershell
npm run docs:maintenance
```

再检查 `docs/maintenance/generated` 的 diff，确认地图和实际代码一致。
