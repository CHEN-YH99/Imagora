# 图片存储与预览流程

## 数据流

```text
worker 得到图片数据
-> packages/storage 保存原图和缩略图
-> 数据库记录 GeneratedImage
-> history/favorites/images 页面读取列表
-> preview/download 接口生成可访问 URL
```

## 关键对象

- `GeneratedImage`：图片记录，包含 taskId、userId、thumbnailUrl、publicUrl、尺寸、可见性、删除状态。
- `ReferenceImage`：参考图上传记录。
- storage key：真实文件存储位置，不应直接暴露为永久公开地址。

## 参考图上传事务

图片审核和 `storage.putObject` 均在数据库事务外执行。上传前按用户与内容哈希定向查重，只复用未删除、未过期且审核通过的参考图；每次新上传使用独立对象键。最终短事务重新检查上传开关和重复记录，只有一个并发请求落库，其余请求在事务外删除各自多余的对象。

上传失败会尝试清理本次对象。落库失败时，先按本次记录 ID 确认是否已提交：确认没有记录才删除对象；若记录已提交则保留。数据库不可用、无法确认提交结果时也保留对象并记录错误，避免误删有效图片。补偿删除失败会记录对象键，保留原始错误；当前没有持久化清理重试队列，需按日志核对并处理残留对象。

## 列表和项目读取

`readImages` 将用户归属、项目、收藏、删除/隐藏过滤、稳定排序、offset/limit 与总数查询下推 PostgreSQL；只加载当前页的任务和收藏关联，详情才读取该任务的退款流水。项目归属与未归档状态在同一读取事务内验证。图片元数据缺失时只通过当前页关联任务恢复，避免加载全部历史任务。

`readImageProjects` 使用数据库计数与每项目一张候选封面，再批量查询显式封面；不会读取整个图片库计算项目数量。项目和封面均限制为当前用户，封面还必须属于该项目。

## 预览和下载

前端预览组件在 `apps/web/components/GeneratedImagePreview.tsx`。

维护重点：

- 列表优先用 thumbnail。
- 大图预览保持原始比例。
- 下载走签名 URL 或受控接口。
- 私有图片不能被其他用户访问。
- 删除通常是软删除，注意列表过滤。

## 可见性和收藏

历史页、收藏页、详情页共享图片状态。改收藏或删除时要验证：

- history 列表变化。
- favorites 列表变化。
- detail 页面权限。
- admin 图片管理是否仍能看到正确状态。
